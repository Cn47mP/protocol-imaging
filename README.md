# 协议映射

《明日方舟：终末地》基地俯瞰成像与标注工程。

协议映射的目标不是简单地连续截图并生成一张大图，而是把固定基地可靠地采集为一个可校验、可恢复、可更新、可标注的地图工程。

## 产品组成

- **协议采集**：作为 MaaEnd 任务运行，负责通用归位、动态探边、原尺寸截图、闭环移动、质量检查和全景生成。
- **成像核心**：不依赖 MaaEnd 的 Go 核心库，负责边界发现、动态规划、运动观测、会话存储、拼接、质量评估和 `.pimap` 工程格式。
- **协议画布**：不依赖 MaaEnd 的独立桌面程序，与采集分开发布；早期留在同一仓库，共享 `.pimap` 读写、迁移和测试数据。

## 为什么接入 MaaEnd

一句话：**让 MaaEnd 负责“可靠地接触游戏”，让协议映射负责“可靠地生成地图”。**

MaaEnd 的价值集中在采集入口：复用用户已经配置好的游戏连接和控制器、任务选项、场景识别、输入调度、取消、日志、进度与分发更新。用户无需再安装一个要求自己找窗口、申请权限、注册全局热键的截图程序，本项目也无需重复维护一套自动化外壳。

MaaEnd 不会直接提高拼接、探边或去动态物算法的质量。它只向成像核心提供 `原始帧 + 输入动作 + 任务生命周期`，边界发现、质量判断、恢复、拼接和工程格式仍属于独立核心；协议画布在运行和发布上也完全不依赖 MaaEnd。

接入是有门槛的：只有 MaaFramework 实测能够提供原始有效尺寸、可靠中键拖动、明确坐标映射和可取消任务时，MaaEnd 才作为正式采集宿主。任何关键能力不满足，都不能为了接入而静默缩图或降低成像质量，核心应改用其他控制器适配器。

## 核心设计

1. 首版不要求用户选择基地，也不依赖基地配置和识别。
2. 任务通用归位到左上后，按动态蛇形路径边移动、边截图、边确认实际边界；探边与采集是同一个过程。
3. 边界观察是首版规划的基础能力；以后增加手选配置或自动识别时，它仍保留最终否决权，并在配置失效时接管。
4. 每一格截图立即保存并评分，低质量截图重拍，任务可以从中断处继续。
5. 首版工程使用会话局部坐标；手选 Base Profile、跨会话规范坐标和自动基地识别在后续版本依次实现。
6. 协议画布作为独立程序和发布单元推进；格式 v1 稳定前与采集同仓，避免过早制造跨仓库兼容成本。

## 当前状态

P0 的核心采集、配准、拼接、工程存储、CLI、MaaEnd 借用式宿主适配器和离线测试链路已经实现。串行全量 Go 测试、格式检查和静态检查通过。

当前仍不能称为实机可用：MaaEnd 当前 Controller 的原尺寸截图、中键拖动、滚轮、取消收尾和输入释放尚未在真实游戏会话中完成 Go/No-Go 探针。MaaEnd 客户端接入还必须通过其正常构建与分发流程，不能依赖会被自动更新覆盖的手工安装。

## 明确不做

- 产线仿真、配方计算或蓝图优化。
- 建筑资产提取或游戏数据挖掘。
- 云端账户、社区图库和在线协作平台。
- 依赖通用全景摄影算法任意旋转、透视扭曲基地画面。

这些边界确保项目始终围绕“固定基地的高质量俯瞰成像”展开。
